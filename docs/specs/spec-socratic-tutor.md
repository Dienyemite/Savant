# Spec — Socratic Tutor

## Purpose
Defines the complete Socratic tutoring system: the chat interface, the
marginalia annotation system, text selection triggers, auto-trigger conditions,
the `chat-store`, streaming patterns, and the Smart Annotation differentiation.
This spec governs `SocraticChat.tsx`, `SelectionTrigger.tsx`,
`MarginaliaAnnotations.tsx`, and `chat-store.ts`.

---

## 1. System Overview

The tutoring system has three distinct activation paths:

| Path | Trigger | Response location | Context type |
|------|---------|-------------------|--------------|
| Auto Socratic | Student fails a block 2+ times | Bottom chat drawer | `"lesson"` |
| Text selection | Student selects text, presses button | Right marginalia panel | `"selection"` |
| Smart Annotation | Student draws ink over text | Right marginalia panel | `"annotation"` |

All three paths call `POST /api/chat` and stream the response. They differ in
how the call is made and where the response is rendered.

## 2. SocraticChat — The Lesson Chat Drawer

File: `src/components/lesson/SocraticChat.tsx`

### Appearance
- Fixed bottom drawer, slides up from below the lesson view
- Width: full lesson column (`max-w-[680px]`, same as lesson content)
- Height: `auto`, shrinks if few messages, max 40vh
- Background: `rgba(0,0,0,0.92)`, `backdrop-filter: blur(4px)`, `border-top: 1px solid rgba(255,255,255,0.12)`
- Font: Courier New 13px

### State
Controlled by `useChatStore.isOpen`. Opened by `triggerFromFailure()`.
The student can also manually open it via a keyboard shortcut `?`.

### Auto-trigger conditions
`SocraticChat` is opened automatically when `useChatStore.triggerFromFailure()` is called.

In `LessonView.tsx`, the trigger fires when:
```ts
// After any block validation failure:
if (answers[blockId]?.attempts >= 2 && answers[blockId]?.validationState === "incorrect") {
  chatStore.triggerFromFailure()
}
```

`triggerFromFailure()` sets `isOpen: true` and pre-populates the first message
from the lesson context (see §4 — `buildLessonContext`).

### Message history
The chat maintains a full conversation history in `messages: ChatMessage[]`.
Each user message appends to the history; each assistant response streams in
and appends on completion. The full message array is sent to `/api/chat` on
each request (for multi-turn context).

Message history is cleared when `exitLesson()` is called.

### User input
- Single-line textarea at the bottom of the drawer
- `Enter` submits (not `Shift+Enter`)
- `Shift+Enter` inserts newline
- Disabled while `isStreaming: true`

## 3. Chat Store Interface

File: `src/store/chat-store.ts`

```ts
interface ChatStore {
  // Lesson chat drawer
  isOpen: boolean
  messages: ChatMessage[]
  isStreaming: boolean
  open(): void
  close(): void
  triggerFromFailure(): void         // opens + fires first Socratic message
  sendMessage(content: string): void // adds user message, fires API call
  clearMessages(): void              // called by exitLesson()

  // Marginalia
  marginaliaEntries: MarginaliaEntry[]
  addMarginaliaEntry(anchorY: number, selectedText: string, type?: MarginaliaEntry["type"]): string
  updateMarginalia(id: string, chunk: string): void    // appends streaming chunk
  finishMarginalia(id: string): void                   // sets isStreaming: false
  removeMarginalia(id: string): void
  clearAllMarginalia(): void                           // called by exitLesson()
}
```

### `triggerFromFailure()` implementation
```ts
triggerFromFailure() {
  set({ isOpen: true })
  // The first AI message is generated by SocraticChat.tsx on mount/open
  // by calling sendMessage with the lesson context — no stored message needed here
}
```

### `sendMessage()` flow
```ts
async sendMessage(content: string) {
  // 1. Append user message
  set(state => ({
    messages: [...state.messages, { id: nanoid(), role: "user", content, timestamp: now() }],
    isStreaming: true,
  }))
  // 2. Call API (SocraticChat.tsx handles this via useEffect on messages change)
  // 3. Stream response into a new assistant message
  // 4. On complete: set isStreaming: false
}
```

## 4. Lesson Context Builder

File: `src/components/lesson/SocraticChat.tsx`

```ts
interface LessonContext {
  lessonTitle: string
  conceptTitle: string
  blockType: LessonBlockType
  blockContent: string
  studentAnswer: string
  attempts: number
}

function buildLessonContext(
  lesson: Lesson,
  slideIndex: number,
  answers: Record<string, BlockAnswer>,
  concepts: Concept[]
): LessonContext {
  const slide = lesson.slides[slideIndex]
  // Find the block the student is currently stuck on
  const failedBlock = slide.blocks.find(b =>
    b.type !== "text" && b.type !== "visual_feedback" &&
    answers[b.id]?.validationState === "incorrect"
  )

  if (!failedBlock) {
    // Fallback: use the last interactive block on the slide
    ...
  }

  const concept = concepts.find(c => c.id === lesson.conceptId)

  return {
    lessonTitle: lesson.title,
    conceptTitle: concept?.title ?? lesson.conceptId,
    blockType: failedBlock.type,
    blockContent: getBlockContent(failedBlock),
    studentAnswer: String(answers[failedBlock.id]?.value ?? ""),
    attempts: answers[failedBlock.id]?.attempts ?? 0,
  }
}

function getBlockContent(block: LessonBlock): string {
  switch (block.type) {
    case "multiple_choice": return `${block.question} Options: ${block.options.join(", ")}`
    case "interactive_slider": return `${block.question} (range: ${block.min}–${block.max})`
    case "drag_drop_match": return block.question
    case "formula_builder": return `${block.question} (tokens: ${block.tokens.join(" ")})`
    default: return ""
  }
}
```

## 5. SelectionTrigger — Text Highlight Annotations

File: `src/components/lesson/SelectionTrigger.tsx`

### Purpose
Detects when the student highlights text in the lesson and offers to generate
a marginalia annotation for that selection.

### Mechanism
1. Listens to `document.selectionchange` event
2. On change: calls `window.getSelection()`, checks if the selection is:
   - Non-empty (`selection.toString().trim().length > 0`)
   - Contained within `containerRef.current` (the lesson content column)
3. If valid: computes the `anchorY` of the selection:
   ```ts
   const range = selection.getRangeAt(0)
   const rect = range.getBoundingClientRect()
   const containerRect = containerRef.current!.getBoundingClientRect()
   const anchorY = rect.top - containerRect.top + containerRef.current!.scrollTop
   ```
4. Shows a floating "annotate" button at `(rect.right + 8, rect.top)` in screen-space
5. On button click: calls `/api/chat` with `contextType: "selection"` and `anchorY`

### Marginalia entry creation
When the button is clicked:
```ts
const entryId = chatStore.addMarginaliaEntry(anchorY, selection.toString(), "selection")
const response = await fetch("/api/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    contextType: "selection",
    messages: [{ role: "user", content: selection.toString() }],
    selectionContext: {
      selectedText: selection.toString(),
      lessonTitle: activeLesson.title,
      conceptTitle: concept.title,
      slideIndex: currentSlideIndex,
    },
  }),
})
await streamToMarginalia(response, entryId, chatStore)
```

### UI — floating annotation button
```tsx
<button
  style={{ position: "fixed", top: rect.top, left: rect.right + 8 }}
  className="text-[11px] font-['Courier_New'] text-white/60 hover:text-white
             border border-white/20 px-2 py-0.5 hover:border-white/40 transition-colors"
>
  annotate
</button>
```
Button disappears when the selection is cleared or the student clicks elsewhere.

## 6. MarginaliaAnnotations — Right Margin Panel

File: `src/components/lesson/MarginaliaAnnotations.tsx`

### Layout
- Fixed right panel, positioned at the right edge of the viewport
- Width: 240px
- Each entry is absolutely positioned by its `anchorY` value
- Entries do not reflow — they stack visually at their anchor positions

### Individual entry
```tsx
<div
  style={{ position: "absolute", top: entry.anchorY, right: 0 }}
  className="w-[240px] pr-4"
>
  {/* Dotted connector line from text to annotation */}
  <div className="absolute left-0 top-[0.7em] w-8 border-t border-dashed border-white/20" />

  <p className="font-['Courier_New'] text-[12px] text-white/60 leading-relaxed text-glow-subtle">
    {entry.content}
    {entry.isStreaming && <span className="animate-pulse">_</span>}
  </p>
</div>
```

### Collision avoidance
If two entries have `anchorY` values within 80px of each other, the later entry
is offset downward by `(80 - gap)` pixels. This is computed in a layout pass
over `marginaliaEntries` sorted by `anchorY`. (Phase 5 Sprint 5.4 refinement.)

### Smart Annotation differentiation (Phase 5 Sprint 5.3)
Smart Annotations (`entry.type === "annotation"`) use slightly different styling:
- Text colour: `text-white/80` (slightly brighter than selection annotations `text-white/60`)
- Left border: `border-l border-white/30 pl-2` (to distinguish from selection)
- No connector line (the ink stroke itself serves as the visual connector)

## 7. Smart Annotation Engine (Phase 5 Sprint 5.3)

The Smart Annotation engine is activated when the user draws an ink stroke that
intersects lesson text. The full flow:

### Step 1 — Stroke completion hook
In `LessonView.tsx` on mount:
```ts
useCanvasStore.getState().setStrokeCommitHandler(async (stroke: InkStroke) => {
  const spatialIndex = useLessonStore.getState().spatialIndex
  if (!spatialIndex?.length) return

  // Step 2: Find which text block(s) the stroke path intersects
  const intersectedBlock = findIntersectedBlock(stroke, spatialIndex)
  if (!intersectedBlock) return

  // Step 3: Compute anchor Y (centre of stroke bounding box, relative to content container)
  const bbox = getHighlightBoundingBox(stroke, viewport, rfContainerOrigin)
  const anchorY = (bbox.top + bbox.bottom) / 2 - contentRef.current!.getBoundingClientRect().top

  // Step 4: Create marginalia entry and call API
  const entryId = chatStore.addMarginaliaEntry(anchorY, intersectedBlock.text, "annotation")
  const response = await fetch("/api/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      contextType: "annotation",
      messages: [{ role: "user", content: intersectedBlock.text }],
      annotationContext: {
        selectedText: intersectedBlock.text,
        blockId: intersectedBlock.blockId,
        blockContent: intersectedBlock.text,
        lessonTitle: activeLesson.title,
        conceptTitle: concept.title,
      },
    }),
  })
  await streamToMarginalia(response, entryId, chatStore)
})
```

### `findIntersectedBlock(stroke, spatialIndex)`
```ts
function findIntersectedBlock(
  stroke: InkStroke,
  spatialIndex: TextBlockSpatialIndex[]
): TextBlockSpatialIndex | null {
  // Convert stroke points to screen-space Y values
  const screenYValues = stroke.points.map(([cx, cy]) =>
    toScreenCoords(cx, cy, viewport, rfContainerOrigin)[1]
  )
  const strokeMinY = Math.min(...screenYValues)
  const strokeMaxY = Math.max(...screenYValues)

  // Find the block whose vertical range overlaps the stroke's vertical range
  return spatialIndex.find(block =>
    block.top <= strokeMaxY && block.bottom >= strokeMinY
  ) ?? null
}
```

### Cooldown
After triggering a Smart Annotation for a given `blockId`, ignore further
strokes over the same block for 10 seconds. Store the cooldown in a `Set`
in `LessonView.tsx`:
```ts
const annotatedBlocks = useRef<Set<string>>(new Set())

// After creating the entry:
annotatedBlocks.current.add(intersectedBlock.blockId)
setTimeout(() => annotatedBlocks.current.delete(intersectedBlock.blockId), 10000)

// Before creating: guard
if (annotatedBlocks.current.has(intersectedBlock.blockId)) return
```

## 8. anchorY Coordinate System

All marginalia entries use a single `anchorY` coordinate system:

> `anchorY` = pixels from the top of the **lesson content container** (`contentRef.current`),
> including the container's current `scrollTop`.

This means if the user scrolls the lesson content column, existing marginalia
entries stay visually pinned to the correct position (they do not drift).

The `MarginaliaAnnotations` container div must also account for scroll:
```tsx
// The marginalia container scrolls together with the content
<div
  ref={marginaliaRef}
  style={{
    position: "absolute",
    top: -contentRef.current?.scrollTop ?? 0,  // offset by scroll
    right: 0,
    width: 240,
  }}
>
  {entries.map(entry => <MarginaliaEntry key={entry.id} entry={entry} />)}
</div>
```

## 9. Lesson Exit Cleanup

When `exitLesson()` is called from `lesson-store`:
1. `chatStore.clearMessages()` — clears lesson chat history
2. `chatStore.clearAllMarginalia()` — removes all marginalia entries
3. `canvasStore.clearStrokeCommitHandler()` — unregisters the Smart Annotation hook

These calls are made in `LessonView.tsx`'s `useEffect` cleanup or in the
`exitLesson` Zustand action (whichever owns the cross-store coordination).
